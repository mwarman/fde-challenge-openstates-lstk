## Ground rules

- **No generated data.** No mocks, fixtures or hand-written records, in the app or in tests (ADR 0002). Anything we see in the UI came from a real sync. A failed jurisdiction shows as failed, not filled in.
- **The API key stays on the backend.** It is read from a git-ignored `.env` and never sent to the browser (R5).
- **Order protects the demo.** Probe, sync, API, table, filters, then group-by and polish (R4).
- **Facts marked `verify`** come from the design's inferences (A5, A6, A9). The probe in step 2 settles them. If the probe contradicts them, fix the plan and the design before going on.

## Step 1. Scaffold (3 to 5 min)

1. Check the toolchain: `node -v` is 24.14.1, which meets the Express native `.ts` floor from ADR 0005. Run `npm -v`.
2. `git init` is not done yet because the directory is not a repo. Ask the user before running it. Add `.gitignore` either way.
3. Root `package.json` with `"workspaces": ["server", "web"]`, `"type": "module"`, and scripts: `dev` (runs both), `probe`, `sync`, `build`, `format`.
4. `server/`: install `express`, `dotenv`. Dev deps: `typescript`, `tsx`, `@types/express`, `@types/node`. Run with `tsx watch src/index.ts`. Port 3001.
5. `web/`: `npm create vite@latest web -- --template react-ts`. In `vite.config.ts` set `server.proxy: { '/api': 'http://localhost:3001' }` so no CORS is needed (ADR 0005).
6. Add `prettier` at the root. Skip oxlint and Vitest for now (see Cuts).
7. Create `.env.example` with `OPENSTATES_API_KEY=`. Ask the user to put the real key in `.env`. Do not read it back or print it.

**Done when:** `npm run dev` starts both servers, and `curl localhost:5173/api/health` reaches Express through the proxy.

## Step 2. Rate-limit probe (3 to 5 min)

Goal: replace the guesses in A5, A6 and A9 with observed facts (ADR 0001 follow-up).

1. `server/src/openstates.ts`: a small `fetch` wrapper that sends the `X-API-KEY` header to `https://v3.openstates.org`, returns status, headers and JSON, and never logs the key.
2. `server/src/probe.ts` runs, in order:
   - One sample: `GET /people?jurisdiction=<code>&per_page=50&page=1` for one state. Save the raw response to `data/probe-sample.json`. Read the real field names (party, current role, district, chamber, image, email). `verify`
   - Check page size and `pagination.max_page` or equivalent. Find the largest `per_page` that is accepted. `verify`
   - Check that `dc` and `pr` are accepted as jurisdictions and that the 52 codes all resolve. `verify`
   - A short burst of sequential requests, then a slightly faster burst, until the first 429 or about 20 requests. Record per request: status, latency, and any `Retry-After` or `X-RateLimit-*` headers.
3. Write a summary to `data/probe-report.json` and print it. Keep the burst small. It spends real quota.
4. Record the findings in the design outline under open question 1: page size, the delay that avoids 429s, the daily or per-minute cap if seen, and whether a full 52-jurisdiction sync fits in one sitting.

**Done when:** we can state the throttle delay, the page size, and the estimated total request count for a full sync, from observation.

**If the probe fails:** a 401 or 403 means the key is wrong or missing, so stop and tell the user. A tight quota means the sync goes ahead in resumable batches (step 3), and the demo uses whatever real jurisdictions finished.

## Step 3. Normalizer and sync module (8 to 12 min)

1. `shared/types.ts`:
   ```ts
   export interface Legislator {
     id: string;
     name: string;
     party: string;
     jurisdiction: string; // state code
     chamber: string;
     district: string;
     title: string;
     imageUrl?: string;
     email?: string;
   }
   export interface JurisdictionStatus {
     code: string;
     state: "ok" | "failed" | "pending";
     count: number;
     syncedAt?: string;
     error?: string;
   }
   export interface CacheFile {
     lastSyncedAt: string | null;
     legislators: Legislator[];
     jurisdictions: JurisdictionStatus[];
   }
   ```
   Field names follow the probe sample, not this sketch, where they differ.
2. `normalize.ts`: map one API person to `Legislator`. If a field is missing, leave it empty or undefined. Do not invent values. Unknown shapes are logged, not silently dropped.
3. `jurisdictions.ts`: the 52 codes (50 states, DC, PR), as confirmed by the probe.
4. `cache.ts`: `readCache()` and `writeCache()`. Write to `cache.json.tmp`, then `rename` (ADR 0006). Return an empty cache if the file does not exist.
5. `sync.ts`: for each jurisdiction, fetch all pages, normalize, and replace that jurisdiction's records in the cache. Details:
   - Sequential, with the throttle delay from step 2.
   - Retry on 429 and 5xx with exponential backoff and `Retry-After` if present, up to a small cap.
   - After each jurisdiction, write the cache. A crash or stop keeps earlier progress (R1).
   - A jurisdiction that fails keeps its previous records, if any, and is marked `failed` with the error text. It is never replaced with made-up rows.
   - A module-level `running` flag blocks concurrent syncs (ADR 0006 consequence). A second start returns the current progress.
   - Set `lastSyncedAt` only when a run finishes. Per-jurisdiction `syncedAt` shows partial freshness (R3).
6. Add a CLI entry `npm run sync` so the first real sync can run without the UI. This is the "seed" the design describes: a real earlier sync.

**Done when:** `npm run sync` fills `data/cache.json` with real records, and the per-jurisdiction counts look plausible against the probe.

## Step 4. API routes (3 to 5 min)

In `server/src/index.ts` (Express 5, async handlers forward errors on their own):

| Route                  | Behavior                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `GET /api/legislators` | Returns `legislators` from the cache. Whole list, no server-side filtering (D4).                                  |
| `GET /api/status`      | Returns `lastSyncedAt`, per-jurisdiction status and counts, and `syncing` with progress (done of 52).             |
| `POST /api/refresh`    | Starts a sync in the background and returns `202` at once. Returns `409` or the current status if one is running. |

- Add a basic error handler that returns JSON and never includes the key.
- Do not add a startup refresh or a timer (D5, ADR 0001).

**Done when:** `curl` on the three routes returns what the cache holds, and `POST /api/refresh` starts a run that `/api/status` shows progressing.

## Step 5. React table and filters (8 to 12 min)

1. `api.ts`: typed fetchers for the three routes, using the shared types.
2. `App.tsx`: load legislators and status on mount. While a sync runs, poll `/api/status` every 2 seconds, then reload legislators when it ends.
3. `StatusBar`: "Last updated" time (or "Never synced"), a Refresh button (disabled while syncing, with progress text), and a scope note: "State legislators from OpenStates. Vacant seats are not shown." (ADR 0003, R6).
4. `LegislatorTable`: columns name, party, state, chamber, district, title. Plain `<table>`, no virtualization (Cuts).
5. `Filters`: name search, state select, party select. Options are built from the loaded data. All filtering runs client-side with `useMemo` (D4).
6. Empty states: no cache yet shows "No data yet. Click Refresh to sync from OpenStates." with no placeholder rows (ADR 0002).

**Done when:** the table shows real synced rows, and the three filters narrow them correctly.

## Step 6. Sync status and error states (2 to 4 min)

1. Show a compact per-jurisdiction status list or panel: count per state, a mark on `failed` and `pending` ones, and the error text on hover or expand (R3, open question 2).
2. Show a banner if the last run was partial: "N of 52 jurisdictions synced. Missing: ...".
3. Show an error message if `/api/*` calls fail, such as the backend not running.

**Done when:** forcing a failure (for example, running with a bad key on a copy of `.env`) shows a failed state in the UI and does not change existing cached rows.

## Step 7. Group-by toggle (cut first if late)

1. Add a toggle: None, By party, By state.
2. Group client-side over the filtered list. Render a header per group with its count, with the rows below. Sort groups by name, and sort rows by name within a group.
3. Keep it in the same table component. No separate views (A3).

**Done when:** switching the toggle regroups the same filtered data, and the counts add up to the filtered total.

## Cuts and why

| Cut                                 | Why it is safe                                                                                                                                                                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Automated tests                     | At this size the demo outranks coverage. Real-data-only (ADR 0002) means no fixtures, so tests would need live calls. A manual smoke check covers it. Add Vitest on the normalizer first if time returns. |
| Scheduled or startup refresh        | A manual button shows freshness. Auto-refresh is deferred (ADR 0001, D5).                                                                                                                                 |
| Pagination or virtualization        | A few thousand rows render fine.                                                                                                                                                                          |
| Detail pages, by-party summary view | Filters and group-by cover the PRD (A3).                                                                                                                                                                  |
| Vacant seats                        | Needs derived data, which ADR 0002 and 0003 rule out.                                                                                                                                                     |
| U.S. Congress, governors            | A second source and merge model (ADR 0003).                                                                                                                                                               |
| Auth, Docker, CI, deployment        | Local only.                                                                                                                                                                                               |
| SQLite                              | JSON file is enough (ADR 0006).                                                                                                                                                                           |
| oxlint                              | Prettier plus `tsc` cover a prototype.                                                                                                                                                                    |
